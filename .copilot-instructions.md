# Instrucciones de Copilot para FM-PREMED

## Contexto del proyecto
- Stack principal: Next.js 16 (App Router), React 19, TypeScript estricto, Tailwind CSS v4, Prisma 7, MariaDB, Better Auth.
- Gestor de paquetes obligatorio: `pnpm`.
- Alias de imports: `@/*` apunta a `src/*`.
- UI base: componentes en `src/components/ui` y patrones de `shadcn`.

## Regla crítica de Next.js
- Este proyecto usa una versión reciente de Next.js con cambios relevantes.
- Antes de proponer APIs de Next.js no triviales, revisar guías en `node_modules/next/dist/docs/` y evitar patrones deprecados.

## Comandos frecuentes
- Desarrollo: `pnpm dev`
- Lint: `pnpm lint`
- Build: `pnpm build`
- Seed Prisma: `pnpm prisma db seed`

## Convenciones de arquitectura
- Mantener estructura por feature en `src/features/<feature>/`:
	- `actions.ts`: entrada de Server Actions.
	- `queries.ts`: lecturas y casos de consulta.
	- `repository.ts`: acceso a datos (Prisma), sin lógica de negocio compleja.
	- `service.ts`: lógica de negocio, validaciones de dominio y auditoría.
	- `schemas.ts` y `types.ts`: contratos de entrada/salida.
- Reutilizar módulos compartidos en `src/shared/*` para auth, auditoría, errores y utilidades.

## Reglas de implementación
- Priorizar componentes de servidor; usar `"use client"` solo cuando sea necesario (estado, efectos, eventos, hooks de cliente).
- Reusar componentes UI existentes antes de crear variantes nuevas.
- Mantener imports absolutos con `@/` cuando aplique.
- No editar archivos generados en `src/generated/prisma/*` manualmente.

## Seguridad y validación
- No hardcodear secretos ni credenciales; usar variables de entorno.
- Evitar SQL crudo con concatenación. Preferir Prisma y filtros tipados.
- Validar entradas con Zod/schemas del feature antes de persistir.
- Aplicar controles de acceso por rol (`ADMIN`, `DOCTOR`, `VIEWER`) en rutas, acciones y navegación.

## Auth y sesiones
- Integración de auth central en `src/lib/auth.ts` y middleware en `src/middleware.ts`.
- Para vistas protegidas, seguir el patrón de `getAuthSession()` + redirección a `sign-in`.

## Persistencia y Prisma
- Si cambias `prisma/schema.prisma`, también actualizar:
	- migraciones correspondientes,
	- seed si aplica,
	- uso de nuevos campos en repositorios/servicios.
- Mantener la conexión Prisma centralizada en `src/lib/prisma.ts`.

## Auditoría y errores
- En operaciones de negocio mutables (crear/actualizar/eliminar), registrar eventos con `auditService` cuando corresponda.
- Usar errores de dominio (`NotFoundError`, `ValidationError`, `ConflictError`, etc.) en vez de `throw new Error` genérico.

## Estilo de código
- TypeScript estricto: evitar `any` salvo casos justificados y acotados.
- Funciones pequeñas, nombres explícitos y sin lógica duplicada.
- No introducir refactors amplios si la tarea es puntual.
- No mezclar cambios funcionales con formateos masivos.

## Qué debe priorizar Copilot al sugerir cambios
1. Mantener comportamiento actual y minimizar regresiones.
2. Seguridad por defecto (validación, autorización, manejo de datos sensibles).
3. Coherencia con el patrón feature-service-repository.
4. Performance razonable (evitar trabajo innecesario en render y consultas).
5. Accesibilidad básica en UI (labels, estados, texto alternativo).
